# FanPulse

Законченный учебный кейс продуктовой аналитики: удержание аудитории спортивного медиасервиса. Подготовлен с помощью ИИ. Все данные синтетические; показатели не относятся к прежней работе автора и не доказывают реальный бизнес-эффект.

## Открыть сначала

- `output/dashboard.html` - автономный дашборд, открывается двойным щелчком без сервера и интернета.
- `output/FanPulse_Отчет.pdf` - портфолио: задача, данные, метрики, эксперимент и решение.
- `docs/INTERVIEW.md` - простое объяснение проекта и текст для hh.

## Задача

Пользователи читают спортивные материалы и не всегда возвращаются. Нужно оценить, помогает ли приглашение в тематическое сообщество удерживать аудиторию лучше, чем email-подборка. Идея отсылает к опыту сегментации аудитории и коммуникаций; в проекте нет данных клиентов или работодателя.

## Что сделано

- Воспроизводимый Python-генератор: 12 000 пользователей, 59 449 событий, 4 источника привлечения.
- База SQLite из 6 связанных таблиц, экспорт исходных данных в CSV.
- 5 аналитических SQL-запросов: воронка, D1/D7/D14, стоимость активации, ITT-эксперимент, когорты с ROW_NUMBER.
- Планирование размера выборки, тест двух долей, 95% ДИ, проверка соотношения групп (SRM).
- HTML-дашборд, PDF-отчёт, CSV агрегатов и JSON с результатами.
- 6 проверок качества данных, 3 теста SQL на ручном примере и 2 теста статистических расчётов. Повторный запуск подтверждён совпадением JSON с результатами.

## Результат симуляции

| Метрика | Email | Community |
|---|---:|---:|
| Зрелая база D7 | 2 517 | 2 487 |
| D7 Retention | 19,19% | 22,80% |
| Отключения коммуникаций за 7 суток | 2,34% | 3,94% |

Разница D7 +3,61 п.п.; 95% ДИ [1,35; 5,86] п.п.; p=0,0017. Отключения выросли на 1,60 п.п. Решение: не рекомендовать массовый запуск только на основании роста retention; согласовать ограничение по отпискам и провести реальный пилот.

Эффект community заранее задан генератором: +4,5 п.п. к дневной вероятности возврата. Найденное различие - демонстрация анализа на искусственной модели, не независимое подтверждение полезности сообществ.

## Запуск

Нужен Python 3.10+; основной анализ и тесты не требуют сторонних пакетов.

```powershell
python src/pipeline.py
python -m unittest discover -s tests -v
```

Первый запуск создаёт или перезаписывает только сгенерированную базу `data/fanpulse.sqlite`, CSV и отчётные HTML/JSON/CSV. Seed 24112026. Срез данных: 31.10.2026, UTC.

Готовый PDF-отчет включен в output/. Публичная версия содержит только аналитический проект, без резюме и персональных контактов.

## Метрики

- Активация: первое чтение материала не менее 30 секунд.
- Dn Retention: доля активированных пользователей с чтением в конкретный календарный день n после активации. Незрелые когорты исключены.
- Возврат за неделю: хотя бы одно чтение в дни 1-7. Это отдельная метрика.
- Стоимость активации: расходы источника / число активированных пользователей источника за период.
- Отключения: доля зрелых участников теста с отключением коммуникаций за 7 суток после назначения.

1-D7 Retention не называется Churn Rate. ROI не рассчитывается: выручка отсутствует.

## Эксперимент

Рандомизация пользователя 50/50 после первого чтения; требуется интерес и согласие на оба канала. Основная метрика D7, анализ по назначенной группе (ITT). Двусторонний тест двух долей, alpha 5%; baseline 19%, MDE +4 п.п., мощность 80% дают план 1627 зрелых участников на группу. Дополнительные показатели разведочные. Подробности: `docs/EXPERIMENT.md`.

## Ограничения

Независимые дневные события упрощают поведение; нет сезонности, реальных сетевых эффектов и экономики продукта. Канал, контент и сообщество меняются вместе. Реальный пилот потребует трекинга сессий и материалов, дедупликации, порога отписок и учёта влияния пользователей друг на друга. Словарь и вероятности генератора: `docs/DATA_DICTIONARY.md`.
